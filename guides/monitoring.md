# Monitoring

Exasol does not have an internal syslog service. Messages generated by Exasol
components are forwarded to the host syslog service. Use a third-party syslog
management tool to subscribe to relevant messages.

In Exasol **2025.1+**, you can also view logs in **Exasol Admin**.

## Syslog Message Structure

Messages contain the Exasol service name in the `IDENT` field:

| Service          | Description                                               |
|------------------|-----------------------------------------------------------|
| `Authentication` | Attempts to authenticate to the host                      |
| `ConfD`          | Events in the ConfD administration interface              |
| `DWAd`           | Database events (start, stop, etc.)                       |
| `Health`         | Host performance (CPU load, RAM, swap) — not storage      |

The message part always starts with `EXA_NODE_ID` (physical node ID), e.g.
`11:`.

### Example Messages

```
May 30 08:03:18 ip-10-0-5-202 Authentication: 11: [confd] Successful authentication with username root
May 30 08:03:18 ip-10-0-5-202 Health: 11: Load 0.42:0.83:0.71; cpus: 2; mem: 13.7 GiB of 15.3 GiB free; swap: 10 GiB of 10 GiB free
May 30 08:05:01 ip-10-0-5-202 ConfD: 11: n0011 User root submitted db_list (11.111)
May 30 08:07:27 ip-10-0-5-202 DWAd: 11: [Exasol] User 0 requests startup of system.
May 30 08:07:28 ip-10-0-5-202 DWAd: 11: [Exasol] System started successfully in partition 75.
```

## Logging Configuration

### Facilities

All Exasol log messages use facility `LOCAL0`. Configure rsyslog to write them
to a separate file:

```bash
# /etc/rsyslog.conf — write to local file
local0.* /var/log/exasol.log

# Forward to external syslog server
local0.* @@syslog.example.com:514
```

### Priorities

Exasol services use all standard syslog priorities:

| Priority      | Description                                    |
|---------------|------------------------------------------------|
| `LOG_EMERG`   | Panic condition (broadcast to all users)       |
| `LOG_ALERT`   | Requires immediate correction                  |
| `LOG_CRIT`    | Critical conditions (e.g. hard device errors)  |
| `LOG_ERR`     | Errors                                         |
| `LOG_WARNING` | Warning messages                               |
| `LOG_NOTICE`  | Non-error conditions requiring attention        |
| `LOG_INFO`    | Informational messages                         |
| `LOG_DEBUG`   | Debug-level messages                           |

Route specific priorities to separate files:

```bash
local0.err /var/log/exasol-errors.log
```

## Thresholds

Set warning thresholds in your syslog monitoring tool. Starting point for CPU
load threshold:

```
number_of_threads_per_node × 1.5
```

**Example:** 2 sockets × 6 cores × 2 (hyperthreading) = 24 threads → threshold
= 36.

## View Logs in Exasol Admin

Available in Exasol **2025.1+**:

1. Open the **Logs** page
2. Select services, log level, and date/time interval → click **Show**
3. Filter output using text or regex in the filter field
